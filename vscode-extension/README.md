# WorkLog Drafter — VS Code 확장

커밋되지 않은 작업과 오늘의 계획을 모아 WorkLog Drafter 서버로 보낸다.
GitHub 커밋만으로는 보이지 않는 **진행 중인 일**이 업무 일지 초안에 들어가게 하는 것이 목적이다.

## 무엇을 보내는가

열려 있는 워크스페이스가 git 저장소이면, 저장소마다 하루 한 건의 세션을 보낸다.

| 항목 | 설명 |
|---|---|
| 미커밋 파일 | 경로와 `+N −M`. `worklog.collectDiff` 가 켜져 있으면 diff 본문도 |
| 미푸시 커밋 | **보내지 않는다.** 사이드바·상태바에만 표시한다 (PRD 7 요청 본문에 자리가 없다) |
| TODO 주석 | 변경된 파일에서 **`TODO:` 로 시작하는 주석**의 파일·줄·내용. 주석 중간에 지나가듯 적힌 것(`// 임시다 TODO: …`), 문자열 리터럴, 문서 본문의 `TODO:` 는 세지 않는다 |
| 오늘 계획 | 사이드바 **계획** 단락의 연필로 연 markdown 문서 한 통. 하루에 하나다 |
| AI 대화 | **오늘 질문을 올린 대화**와 **지금 열어 둔 빈 곳이 아닌 대화**. 질문·답변과 물어본 횟수 |
| 편집 타임라인 | 파일별 첫 저장·마지막 저장 시각과 저장 횟수 |
| 브랜치·remote URL | 어느 저장소의 작업인지 서버가 알아보기 위한 값 |

같은 (사용자·저장소·브랜치·날짜) 세션은 **덮어쓰기(UPSERT)** 된다. 여러 번 보내도 건수가 늘지 않는다.

## 설치

1. `.vsix` 파일을 받는다 (배포처: 팀 공유 폴더 또는 `npm run package` 로 직접 만든 파일).
2. VS Code → 확장 패널 → 우상단 `⋯` → **Install from VSIX…** → 파일 선택.
   - 터미널을 선호하면: `code --install-extension worklog-drafter-0.1.0.vsix`
3. VS Code 를 다시 시작한다.

## 최초 설정

전송하려면 **개인 API Key** 가 필요하다. 대시보드에 로그인해서 발급받는다.

1. 대시보드 → **설정** → API Key **발급**
2. 발급 직후 한 번만 보이는 `wl_...` 키를 복사한다. 창을 닫으면 다시 볼 수 없다
3. VS Code 에서 명령 팔레트(`Cmd+Shift+P`) → **`WorkLog: 서버 주소·API Key 입력`**
   - **1/2 서버 주소** — 백엔드 주소다. 팀이 서버를 한 대만 띄웠다면 그 PC 의 주소를 적는다.
     예) `http://192.168.0.224:8080`. 스킴을 빼거나 `/api`·끝 슬래시를 붙여도 알아서 다듬는다
   - **2/2 API Key** — 복사한 `wl_...` 를 붙여넣는다
   - 사이드바 제목의 열쇠 아이콘, 상태바의 경고를 눌러도 같은 입력창이 뜬다
   - 설정 화면(`Cmd+,` → `worklog`)에서 직접 넣어도 된다

> **기본 주소는 `http://localhost:8080` — 자기 컴퓨터다.** 서버를 띄운 PC 가 따로 있는데
> 이 값을 그대로 두면 `서버에 연결할 수 없음` 으로 막힌다. 그때 뜨는 알림의
> **서버 주소 설정** 을 누르거나, 명령 팔레트 → `WorkLog: 서버 주소 설정` 으로 바꾼다.

## 사이드바

활동 표시줄의 **WorkLog Drafter** 아이콘을 누르면 **지금 무엇이 서버로 갈지** 보인다.
전송하기 전에 확인할 수 있어서, 상태바의 숫자 하나만 보고 짐작하지 않아도 된다.

```
전송 완료 09:48:36 · 미커밋 파일 5개
▾ uxis-co-kr/2026-pknu-3day · VsPeristalsis_dashboard
    계획
  ▸ 미커밋 파일 5개
      tracked.txt   +2 −1
      new.ts        +4 −0
  ▸ 미푸시 커밋 2개
      fix: 재생성 후 흰 화면        be292b4
      feat: 재생성·Mattermost 전송   860e66b
  ▸ AI 대화 2세션
    ▸ 계획 작성 방식 개선          09:22–10:15 · 9개
    ▸ 서버 내부 아이피 접근        9/10 07:10–07:33 · 4개
  ▸ TODO 2개
      출석 중복 검증 마무리   new.ts:2
  ▸ 저장 이벤트 1개
      tracked.txt   2회
▸ 서버에 저장된 내역            최근 7일 · 4건
```

- 파일이나 TODO 를 누르면 **그 자리로 열린다** (TODO 는 해당 줄로).
- **미푸시**는 커밋했지만 아직 원격에 올리지 않은 것이다. 이 구간은 GitHub 수집기가
  보지 못하므로 (원격에 없으니 API 에 안 나온다) 여기서만 보인다. 서버로는 보내지 않는다.
  한 번도 푸시하지 않은 브랜치는 비교 기준이 없어 `셀 수 없음` 으로 나온다 — 0 과 다르다.
- **계획** 줄을 **두 번 누르면** 계획 문서가 열린다. 한 번은 고르기다 (탐색기와 같다).
  마우스를 올리면 뜨는 **연필**은 한 번으로 열린다. 아직 적지 않았으면 `미작성` 이라고 붙는다.
- 맨 위 줄이 마지막 전송 결과다. 실패하면 사유가 그대로 뜬다.
- 뷰 제목 오른쪽에 **전송 · 새로고침** 버튼이 있다.
- 파일을 저장하면 1초 뒤 자동으로 갱신된다. diff 본문은 화면에 쓰지 않으므로 받아 오지 않는다.
- **AI 대화**는 **오늘 질문을 올린 것**과 **지금 열어 둔 것**을 함께 보여 주고, 둘 다 서버로
  간다. 오늘 물었으면 닫았더라도 남고(닫는 순간 그날 기록이 지워지면 안 된다), 열어 두고
  아직 묻지 않았거나 어제부터 붙들고 있는 대화도 올라온다. 질문이 하나도 없는 대화는 넣지
  않는다. 닫은 지난 대화는 보이지 않는다 — 기록 파일은 남지만 열려 있는 세션만 본다.

### 서버에 저장된 내역

맨 아래 **서버에 저장된 내역**을 펼치면 최근 7일치 **내** 기록을 서버에서 받아 날짜별로
보여 준다. 위쪽 "오늘 보낼 내용" 은 아직 보내지 않았을 수도 있는 지금 상태고, 여기는
**서버가 실제로 받은 것**이다. 보낸 것이 들어갔는지 VS Code 안에서 확인하는 자리다.

- **펼칠 때만** 부른다. 접어 두면 서버를 부르지 않는다
- 지금 열어 둔 저장소의 것만 보여 준다
- 서버에 닿지 못하면 사유가 그 자리에 뜬다. 위쪽 "오늘 보낼 내용" 은 그대로 돈다

## 계획 적기

사이드바 **계획** 단락의 **연필**(또는 명령 팔레트 → **`WorkLog: 오늘 계획 작성·수정`**)
을 누르면 가운데에 **계획 문서 탭**이 열린다. 창 맨 위의 한 줄 입력이 아니라 보통 편집기라
여러 줄·붙여넣기·되돌리기가 그대로 된다.

**문서 한 통이 오늘 계획 하나다.** 한 줄을 한 건으로 세지 않으므로 제목·목록·들여쓰기를
markdown 으로 마음껏 쓸 수 있고, 적은 모양 그대로 업무 일지 초안에 들어간다.

```markdown
<!-- WorkLog 계획 · 2026-09-11 (금)
     폴더: /Users/me/work/app
     오늘 할 일을 적고 저장(Cmd+S)하세요. 이 문서 한 통이 오늘 계획입니다.
     사이드바의 "계획" 과 오늘 업무 일지의 "계획 / TODO" 에 반영됩니다.
     제목·목록·들여쓰기는 적은 그대로 갑니다. 이 주석만 빼고 보냅니다.
     지운 내용은 계획에서도 지워집니다. -->

## 오전
- 확장 서버 주소 명령

## 오후
- 계획 문서 탭
  - 문서 한 통이 하루 계획
```

- **저장할 때** 반영된다. 상태바에 "오늘 계획을 저장했습니다" 가 잠깐 뜬다.
  문서를 비우면 "내용이 비어 오늘 계획을 비웠습니다" 라고 적는다 —
  아무 말이 없으면 저장이 안 먹은 것과 구별되지 않는다
- **문서가 곧 그날 계획 전부다.** 지우고 저장하면 그 내용도 없어진다
- 우리가 넣은 안내 주석만 빼고 **적은 그대로** 보낸다. 목록 표식도 떼지 않는다
- 폴더가 여럿이면 **어느 폴더의 계획인지 먼저 묻는다.** 폴더마다 하는 일이 다르다.
  머리말의 `폴더:` 줄이 그 표시라, **창을 새로 고쳐 탭이 복원된 뒤에 저장해도** 제자리로 간다
- 문서는 확장의 저장 공간에 두므로 **작업 저장소에는 남지 않는다.** git 에 잡히지 않고,
  이 파일의 저장은 "저장 이벤트" 로도 세지 않는다

## 쓰는 법

| 방법 | 동작 |
|---|---|
| 상태바 `미커밋 N파일 · 미푸시 M` 클릭 | 지금 전송 |
| 명령 팔레트 → `WorkLog: 지금 전송` | 같음 |
| 사이드바 **계획** 단락의 연필 (또는 `WorkLog: 오늘 계획 작성·수정`) | 계획 문서 탭을 연다. 저장하면 반영된다 |
| 명령 팔레트 → `WorkLog: 서버 주소·API Key 입력` | 주소와 키를 차례로 넣는다 (재발급했을 때) |
| 명령 팔레트 → `WorkLog: 서버 주소 설정` | 백엔드 주소만 바꾼다 (다른 PC 의 서버를 볼 때) |
| 그냥 두기 | 10분마다 자동 전송, VS Code 종료 시 한 번 더 |

**알림은 직접 누른 것에만 뜬다.** 주기 전송·시작·종료 전송은 조용히 돌고 상태바만 바뀐다.
직접 누른 전송은 결과를 그대로 알린다 — 보냈는지, 보낼 것이 없었는지, 왜 실패했는지.

전송이 되면 대시보드 홈의 **미커밋 세션** 카드가 올라가고, 그날 초안을 생성하면
"진행 중 / 미커밋" 과 "계획 / TODO" 에 반영된다.

## 설정 항목

| 키 | 기본값 | 설명 |
|---|---|---|
| `worklog.serverUrl` | `http://localhost:8080` | 백엔드 주소. `/api` 는 붙이지 않는다. **기본값은 자기 컴퓨터다** |
| `worklog.apiKey` | (빈 값) | 대시보드에서 발급한 개인 키 |
| `worklog.intervalMinutes` | `10` | 자동 전송 주기(분). 최소 5. AI 대화는 그 사이에도 쌓인다 |
| `worklog.collectDiff` | `true` | 끄면 파일 경로와 변경 줄 수만 보낸다 |

## 문제가 생기면

상태바에 사유가 한 줄로 뜬다. 자세한 기록은 **출력 패널 → WorkLog** 채널에 있다.

| 상태바 | 뜻 | 할 일 |
|---|---|---|
| `API Key 미설정` | 키가 비어 있다 | 위 최초 설정 |
| `API Key 오류` | 서버가 401/403 을 돌려줬다 | 대시보드에서 재발급 → **상태바를 클릭**하면 입력창이 뜬다 |
| `서버에 연결할 수 없음` | 주소가 틀렸거나 서버가 꺼져 있다 | **상태바를 클릭**하면 주소 입력창이 뜬다 |
| `서버 응답 없음` | 10초 안에 응답이 없었다 | 같음. 주소가 맞으면 백엔드 로그 확인 |
| `서버 오류 5xx` | 백엔드가 실패했다 | 출력 패널의 응답 본문 확인 |

전송 실패는 확장을 멈추지 않는다. 다음 주기에 다시 시도하고, 같은 세션을 덮어쓴다.

## 알아 둘 것

- **저장 이벤트와 계획은 재시작해도 남는다.** VS Code 의 `globalState` 에 그날 날짜와 함께
  적어 두고, 날이 바뀌면 버린다. 서버가 `editTimeline` 을 통째로 덮어쓰기 때문에, 메모리에만
  두면 재시작 후 첫 전송이 그날 쌓인 기록을 지운다.
- **워크스페이스가 git 저장소이기만 하면 등록 여부와 무관하게 보고한다.** 개인 프로젝트를
  열어 두면 그 미커밋 작업도 올라간다 (BACKLOG §5 결정 3번).
- API Key 는 VS Code 설정에 평문으로 저장된다. 설정 동기화를 켜 두었다면 계정에 함께 올라간다.

## 수집기 테스트

무엇이 서버로 갈지 **보내기 전에** 확인할 수 있다. VS Code 를 띄우지 않고 수집기만 돌린다.

```bash
npm run compile
npm run preview                       # 현재 폴더
npm run preview -- ~/some/repo        # 다른 저장소
npm run preview -- . --no-diff        # diff 본문 없이
npm run preview -- . --plan "메모"    # 계획 메모를 넣은 상태로
npm run preview -- . --full           # 서버로 갈 JSON 전체
```

출력은 이런 모양이다.

```
remoteUrl   https://github.com/uxis-co-kr/2026-pknu-3day.git
branch      VsPeristalsis_dashboard
workDate    2026-09-10   (KST)

미커밋 4개
  +1 −0  staged.txt  diff 8줄
  +2 −1  tracked.txt  diff 11줄
  +0 −0  blob.dat  diff (없음)
  +4 −0  new.ts  [새 파일]  diff 5줄

TODO 2개
  new.ts:2  출석 중복 검증 마무리
```

**전송은 하지 않는다.** 읽기만 한다.

알아 둘 것:

- `edit timeline` 은 항상 0 이다. VS Code 의 파일 저장 이벤트로만 쌓이므로 밖에서는 재현되지 않는다.
- 바이너리 파일은 `+0 −0`, diff 없음으로 나온다. 본문을 보내지 않는다.
- diff 는 파일당 200줄까지다. 그보다 길면 마지막에 생략 줄이 붙는다.
- `origin` 이 없는 저장소는 건너뛴다 — 서버가 어느 리포인지 알 수 없기 때문이다.

### VS Code 안에서 확인하기

전송까지 포함한 전체 경로는 실제 VS Code 로 본다.

- **F5** — Extension Development Host 가 뜬다. 설치 없이 수정한 코드를 바로 확인할 수 있다.
- 설치본으로 볼 때는 명령 팔레트 → `WorkLog: 지금 전송` → **출력 패널 → WorkLog** 채널.
  전송한 세션 id 와 미커밋 파일 수가 한 줄로 찍힌다.

## 개발

```bash
npm install
npm run compile        # tsc -p ./
npm run watch          # 감시 컴파일
npm run package        # .vsix 생성
```

F5 로 **Extension Development Host** 를 띄우면 설치 없이 디버깅할 수 있다.
