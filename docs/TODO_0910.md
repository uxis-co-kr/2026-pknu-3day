## 1. 오늘 회의에서 정한 것

### 1-1. 로그인 · 회원 (담당자 1 / 회원 조회 API 는 담당자 2)

| 회의 내용 | 지금 상태 | 할 일 |
|---|---|---|
| 회원 조회 API 를 주면 **그 기준으로 로그인** | GitHub OAuth 로그인이 곧 회원가입이다 | 자체 로그인 화면 → 회원 조회 API 로 검증 → JWT |
| 설정에서 **GitHub · VS 연동** | GitHub 은 로그인 수단이고, VS 는 API Key 발급만 있다 | 설정에 "연동" 영역 신설. GitHub 은 로그인 → **내 계정에 연결**로 의미가 바뀐다 |
| 로그인 화면 **아래에 관리자 콘솔** 진입 | 로그인 화면은 "GitHub로 로그인" 버튼 하나 | 로그인 폼 아래에 관리자 콘솔 링크 |

#### 회원 조회 API — 받았다 (9/10 10:44)

| 항목 | 값 |
|---|---|
| BASE URL | 사내 API 서버. **주소는 `backend/.env` 의 `WAPLE_API_BASE_URL` 에만 둔다** |
| 인증 | 헤더 `X-Api-Key: <키>`. **키는 `backend/.env` 의 `WAPLE_API_KEY` 에 둔다 — 커밋 금지** |

| 기능 | Method | 경로 |
|---|---|---|
| 사용중인 와플 회사 목록 | GET | `/core/v1/companies` |
| 특정 회사의 재직중 사원 목록 | GET | `/core/v1/companies/{coSeq}/employees` |
| 특정 사원 이름 조회 (사용유무 무관) | GET | `/core/v1/companies/{coSeq}/employees/{empSeq}` |

**응답 모양** — 두 엔드포인트를 실제로 호출해 확인했다. 값은 사내 정보라 적지 않는다.

```
{ status: boolean, message: string, data: { <이름>: [...] } }

  /companies            → data.companies[]  { coSeq: number, coNm: string }
  /companies/{n}/employees → data.employees[] { empSeq: number, empNm: string }
```

### 🔴 로그인에 쓸 수 있는 값이 없다

**사원 정보에 `empSeq` 와 `empNm` 밖에 없다.** 이메일도, 비밀번호도, 부서도, GitHub 계정도
없다. 이 API 만으로는 **본인 확인이 불가능하다** — 목록에서 자기 이름을 고르는 것은 인증이
아니라 선택이다. 아무나 남의 이름을 고를 수 있다.

게다가 **같은 이름을 가진 사원이 실제로 있다** (`empSeq` 가 다른 동명이인). 이름만으로는
사람을 특정할 수도 없다.

그래서 로그인은 이 API 하나로 끝나지 않는다. 적어도 아래 중 하나가 더 필요하다.

| 방법 | 내용 | 비용 |
|---|---|---|
| **A. 사원 선택 + GitHub OAuth** | 목록에서 자기 사원을 고르고, **GitHub 로그인으로 본인을 증명**한다. 한 번 이으면 다음부터 GitHub 로그인만으로 들어온다 | 지금 있는 GitHub OAuth 를 그대로 쓴다. **가장 싸다** |
| B. 초대 코드 | 관리자가 사원별 1회용 코드를 발급 | 관리자 콘솔에 발급 화면이 필요하다 |
| C. 와플 인증 API | 와플 쪽에 로그인 검증 API 가 따로 있는지 확인 | 있으면 가장 깔끔하다. **먼저 물어볼 값어치가 있다** |

**A 를 권한다.** GitHub OAuth 는 이미 붙어 있고, 우리 서비스는 어차피 GitHub 활동을
모아야 하므로 GitHub 계정 연결이 **필수**다. 사원 선택은 그 위에 한 번만 얹으면 된다.
다만 C 를 먼저 확인해 보는 편이 좋다 — 있으면 A 보다 낫다.

**그 밖에 걸리는 것 둘**

1. **회사가 둘인데 이름이 같다** — `coSeq` 값이 다른 두 회사의 `coNm` 이 같다.
   어느 쪽 사원 목록을 쓸지 정해야 한다.
2. **프론트에서 직접 못 부른다** — 사내망 주소이고 헤더에 키가 들어간다. 브라우저에서
   부르면 키가 노출되고 사외에서는 접근도 안 된다. **백엔드가 대신 부르고 우리 API 로
   중계**해야 한다. 담당자 2 의 작업이 하나 는다.
3. **우리 `users` 와 잇는 방법** — `empSeq` 를 `users` 에 저장해 두고 대조한다.
   컬럼 추가가 필요하다 (role 과 같은 마이그레이션에 묶으면 된다).

이 결정은 백로그 §2(자체 회원 체계)와 F-4·F-5 를 **대체한다.** 회원을 우리가 새로 만드는 게
아니라 **이미 있는 회원 조회 API 를 쓰는 쪽**으로 정해졌으므로, V4 마이그레이션과 자체
회원가입 폼은 범위에서 빠진다. 다만 `users` 에 **role 컬럼은 여전히 필요하다** — 관리자
콘솔에 들어갈 수 있는 사람을 가려야 한다 (§1-3).

## 3. 오늘 발견한 문제

### 3-1. 18:00 자동 생성이 "버튼 눌러 생성" 과 충돌한다 ❓

`DraftScheduler` 가 매일 18:00 KST 에 **전 사용자 초안을 자동 생성한다** (`DRAFT_SCHEDULE_CRON`,
현재 설정돼 있음). "전송하면 초안으로 바로 만들지 말고 생성/재생성을 눌렀을 때 모아서 만들자"는
방향과 어긋나는 유일한 지점이다.

VS 전송 자체는 초안을 만들지 않는다 — `VscodeSessionService.upsert` 는 세션만 저장하고,
초안은 `POST /drafts/generate` 를 부를 때만 만들어진다. **자동 생성만 예외다.**

끄거나 시각을 바꾸는 건 설정 한 줄이지만, 없앨지는 기획 판단이라 손대지 않았다. §5-1.

### 3-2. 미푸시 커밋을 보낼 자리가 계약에 없다 🔴

커밋했지만 **아직 푸시하지 않은 구간은 GitHub 수집기가 볼 수 없다.** 원격에 없으니 API 에
나오지 않는다. 개발자 입장에서는 분명히 한 일인데 대시보드에도 초안에도 없다.

확장은 오늘부터 이걸 **사이드바와 상태바에 표시한다** (`06c1b67`). 그러나 서버로는 보내지
않는다 — `POST /vscode/sessions` 요청 본문(PRD §7)에 담을 자리가 없다.

초안의 "진행 중 / 미커밋" 에 들어가야 그날 한 일이 온전해진다. **커밋 메시지는 이미 사람이 쓴
요약이라 미커밋 파일 목록보다 초안에 더 어울린다.**

넣으려면: PRD §7 스키마 → `SessionRequest` → `vscode_sessions` 컬럼 → `DraftTemplate`.
담당자 2 와 맞춰야 한다. §5-4.

### 3-3. 초안 템플릿이 계획 여러 건을 한 줄로 붙인다 🟡 (담당자 2)

확장이 계획 메모를 여러 건 받게 바뀌었고(`a79ef18`), 서버 계약을 지키려고 **줄바꿈으로 이어**
한 문자열로 보낸다. `DraftTemplate.plans()` 가 `planNote` 를 한 줄로 취급해 `- ` 하나만 붙이므로,
초안의 `## 계획 / TODO` 에 여러 계획이 **한 덩어리 불릿**으로 들어간다.

읽는 데 문제는 없지만 줄마다 불릿이 되는 편이 맞다. `planNote.split("\n")` 한 줄이면 된다.
