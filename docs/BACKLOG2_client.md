## C-1. AI 대화 세션 — 무엇이 어긋나는가 🔴

> "ai 대화 세션 과정 파악 좀. 뭐가 동기화가 이상한듯"

### 확인한 것

세션 **개수는 맞다.** 파일과 DB 를 대조했다.

```
파일(KST 기준 오늘 대화가 있는 세션)   4개
DB  vscode_sessions.ai_sessions        4개
```

**틀린 것은 질문 수다.**

| 세션 | 실제 질문 | 화면에 뜨는 수 |
|---|---|---|
| `f712b7e6` | **60** | 12 |
| `1d357bb4` | **54** | 12 |
| `d4425159` | **33** | 12 |
| `24e637a3` | 2 | 2 |

### 원인 — 두 가지다

**① `promptCount` 가 자른 뒤의 개수다** (`aiSessions.ts`)

```ts
const MAX_PROMPTS = 12
...
if (prompts.length < MAX_PROMPTS) prompts.push(...)   // 12개까지만 담는다
...
promptCount: prompts.length                            // ← 담은 개수를 세고 있다
```

프롬프트를 12개로 자르는 것 자체는 의도한 것이다(프롬프트가 넘치면 일지 생성이 감당하지
못한다). 그런데 **개수까지 12로 보고한다.** 60번 물어본 세션이 "프롬프트 12개" 로 보이니
숫자가 실제와 어긋나 보인다.

**고치는 법**: 세는 것과 담는 것을 나눈다. `total` 을 따로 세고 `prompts` 만 자른다.
화면은 "12개 표시 / 전체 60개" 처럼 둘 다 보여 준다.

**② 숫자가 전송할 때만 갱신된다**

확장은 켤 때·30분마다·끌 때 보낸다. **대화는 그 사이에도 계속 쌓인다.** 방금도 마지막
전송(17:49) 이후 지금 세션이 계속 자라고 있다. 대시보드는 30초마다 갱신되지만, 서버에
있는 값 자체가 마지막 전송 시점의 것이다.

**고치는 법 셋**

| 방법 | 내용 | 판단 |
|---|---|---|
| A. 주기를 줄인다 | 30분 → 5~10분 | 가장 싸다. 다만 전송이 잦아진다 |
| B. 세션 파일을 지켜본다 | `~/.claude/projects/**` 를 감시해 바뀌면 보낸다 | 정확하다. 대화할 때마다 보내므로 빈도 제한이 필요하다 |
| C. 사이드바만 즉시 갱신 | 보내지 않고 화면만 다시 읽는다 | 내 화면은 맞아지지만 **서버는 그대로**다 |

**A + C 를 권한다.** 사이드바는 파일 변화에 맞춰 바로 고쳐 그리고(C), 서버로는 조금 더
자주 보낸다(A). B 는 전송이 너무 잦아진다.

### 함께 볼 것

- **브랜치를 바꾸면 같은 대화가 두 번 들어간다.** 세션 키가 `(사용자, remote, 브랜치, 날짜)`
  인데 AI 대화는 **폴더 단위**다. 오전에 A 브랜치, 오후에 B 브랜치로 일하면 두 행이 같은
  대화를 각각 들고 있다. 일지 생성 때 중복으로 읽힌다
  → 대화를 세션이 아니라 **(사용자, 폴더, 날짜)** 로 따로 두거나, 일지 만들 때 세션 id 로 중복을 없앤다

## C-2. 계획 작성 창 🟡

> "계획 작성을 위 패널이 아니라 중간에 창을 만들어서 작성하는게 편할 것 같다"

**지금**: `vscode.window.showInputBox` — VS Code 창 **맨 위**에 한 줄짜리 입력이 뜬다.
긴 계획을 쓰기 어렵고, 시선이 위로 튄다.

**선택지**

| 방법 | 모양 | 비용 |
|---|---|---|
| **A. 임시 문서** | 새 탭을 열어 거기 쓰고 닫으면 저장 | 여러 줄을 쓸 수 있다. VS Code 다운 방식 |
| B. Webview 패널 | 가운데에 자체 창 | 원하는 모양을 만들 수 있으나 HTML·통신을 직접 짠다 |
| C. 사이드바에서 인라인 편집 | 계획 항목을 그 자리에서 고친다 | 트리 뷰라 자유롭게 편집하기 어렵다 |

**A 를 권한다.** `workspace.openTextDocument({ content, language: 'markdown' })` 로 탭을 열고,
저장하거나 닫을 때 내용을 계획으로 받는다. 여러 줄·붙여넣기·되돌리기가 전부 공짜로 따라온다.
"중간에 창" 이라는 요청에 가장 가깝고, Webview 보다 훨씬 싸다.

> B 를 원하시면 그것도 가능하다. 다만 계획 한 줄을 받자고 Webview 를 들이는 것은
> 과해 보인다.

## C-3. 확장이 가져올 정보 — 내일 정한다 ⬜

> "익스텐션에서 어떤 정보 갖고 올지 내일 얘기해보기"

**지금 가져오는 것** (폴더마다)

| 항목 | 쓰이는 곳 |
|---|---|
| 미커밋 파일 (경로·`+N −M`·diff 본문) | VSCode 내역, 일지 "진행 중 / 미커밋" |
| TODO·FIXME 주석 | 일지 "계획 / TODO" |
| 계획 메모 | 일지 "계획 / TODO" |
| 저장 이벤트 (파일별 첫·마지막 저장, 횟수) | VSCode 내역 (얼마나 손댔는지) |
| 브랜치·remote URL·마지막 커밋 시각 | 세션 키, 리마인드 판단 |
| AI 대화 (사용자가 친 말) | VSCode 내역, 일지 재료 |
| **미푸시 커밋** | **화면 표시만.** 서버로 보내지 않는다 (계약에 자리 없음) |

**내일 정할 것**

1. **미푸시 커밋을 서버로 보낼지** — 커밋했지만 안 올린 구간은 GitHub 수집기가 못 본다.
   커밋 메시지는 이미 사람이 쓴 요약이라 일지 재료로 좋다. `POST /vscode/sessions` 스키마 변경
2. **diff 본문을 계속 보낼지** — 지금은 파일당 200줄까지 보낸다. 개인 프로젝트를 열어 두면
   그 코드도 서버로 간다 (§확장 README 에 주의로 적어 둠)
3. **AI 대화에 답변도 담을지** — 지금은 질문만. 답변까지면 데이터가 몇 배가 된다
4. **미등록 리포의 작업도 보낼지** — 지금은 git 저장소이기만 하면 보낸다
5. **TODO 를 바뀐 파일에서만 찾을지** — 지금 그렇다. 저장소 전체를 훑으면 오늘 한 일과
   무관한 TODO 까지 올라온다

## 9/11 에 더 찾은 것 — **대화가 통째로 빠지고 있었다**

C-1 을 고치고 나서도 숫자가 맞지 않아 다시 봤더니, 세션 **개수 자체**가 틀리고 있었다.

VS Code 안에서 Claude Code 를 쓰면 편집기가 사람이 친 말 **앞에**
`<ide_opened_file>...</ide_opened_file>` 안내를 한 덩어리 끼워 넣는다. 수집기는 덩어리를
**이어 붙인 뒤** 첫 글자가 `<` 인지 보고 버렸다. 그래서 그 질문이, 나아가 남은 질문이
하나도 없는 그 대화가 통째로 사라졌다.

```
9/11 오전 이 저장소:  파일에 대화 3개  →  수집기가 본 것 2개
```

`f20fcbf` 에서 **덩어리마다** 판단하도록 고쳤다. 위 C-1 의 "세션 개수는 맞다" 는
VS Code 밖에서 쓴 날의 기록을 본 것이었다.

### C-2 에 딸린 것 — 지운 계획이 서버에 남았다

계획을 문서에서 쓰게 되면서 "지운 줄은 계획에서도 지워진다" 가 약속이 됐는데, 서버가 빈
계획을 무시하고 있었다 (`d92b1db` 에서 고침). 확장이 재시작하면 메모를 잃던 시절의 방어인데,
지금은 `globalState` 에서 되살리므로 빈 값은 "지웠다" 는 뜻이다.
