## 2. 오늘 받은 피드백 (9/10 저녁)

### 2-1. 내부 IP 로 접속 🔴

> "로컬 호스트가 아니라 내부 ip 에서 접속할 수 있게. 나랑 친구랑 로컬 호스트 접속 주소가 다르다 —
> 난 224, 친구는 218"

**지금 무엇이 막는가**

| 자리 | 값 | 문제 |
|---|---|---|
| `FRONTEND_URL` | `http://localhost:5173` | OAuth 콜백이 **자기 PC 로만** 되돌아온다 |
| 확장 `worklog.serverUrl` | `http://localhost:8080` | 남의 PC 에서 열면 자기 백엔드를 부른다 |
| vite `server.host` | `true` (열려 있음) | ✅ 이미 됨 |

담당자 2 가 **state 를 서명으로 옮겨** 쿠키가 안 붙던 문제는 이미 풀었다. 남은 것은 **주소를
어디서 정하느냐**다.

**방법 셋**

| 방법 | 내용 | 판단 |
|---|---|---|
| **A. 요청에서 유추** | `FRONTEND_URL` 대신 콜백 요청의 `Origin`/`Referer` 로 돌아갈 주소를 정한다 | 각자 자기 주소로 돌아온다. **아무 설정도 필요 없다** |
| B. 허용 목록 | `FRONTEND_URLS` 에 여러 주소를 적고 그중 맞는 것으로 | 안전하지만 사람이 늘 때마다 고쳐야 한다 |
| C. 각자 .env | 사람마다 자기 IP 를 적는다 | 지금 상태. 실수하기 쉽다 |

**A + B 를 함께 권한다** — 요청에서 유추하되 **사내망 대역만 허용**한다. 아무 주소로나
돌려보내면 열린 리다이렉트가 된다 (§2-2 와 직결).

> 피드백의 "env 파일이 아니라 api 그때그때 불러서" 는 이 이야기로 읽었다.
> 다르게 뜻하신 것이면 알려 주기 바란다.

**확장 쪽**: ✅ **9/11 완료** (`1cb4cb5`). `WorkLog: 서버 주소·API Key 입력` 이 주소(1/2)를
먼저 묻고 키(2/2)를 묻는다. `WorkLog: 서버 주소 설정` 으로 주소만 바꿀 수도 있다. 연결에
실패하면 지금 부르고 있는 주소를 알림에 실어 고칠 자리로 보낸다.

**리포 목록을 팀 전체로 (9/11 결정 — 9/10 을 뒤집는다).** 리포는 한 사람만 등록할 수 있다
(`repos.full_name` UNIQUE, 수집이 등록자 토큰으로 돈다). 그런데 목록은 "내가 등록한 것만"
이었다. 같은 리포에서 일하는 팀원의 화면은 **늘 비어 있고**, 등록하려 하면 막히고, 이미
덮여 있다는 것을 알 길도 없었다. 목록만 팀 전체로 돌린다.

- 활동·VS 기록은 그대로 **각자의 것만** 본다. 바뀐 것은 리포 목록 하나다
- 지우는 것은 등록한 사람만 (`REPO_NOT_OWNED`). 화면에서도 남의 리포는 삭제 버튼이 잠긴다
- 전체 동기화도 같은 집합을 돈다 — 보이는 것과 도는 것이 다르면 팀원이 눌러도 아무 일이
  없다

> 세션 10개 중 6개에 있었다. 남긴 것이 있으면 그것을 쓰고, 없는 세션만 첫 질문 40자로
> 만든다. 처음 훑을 때 `type` 값을 다 세지 않고 user/assistant 만 보고 단정한 것이 원인이다.

> **함께 고친 버그 — VS Code 안에서 쓴 대화가 통째로 빠지고 있었다.** 편집기가 사람이 친
> 말 **앞에** `<ide_opened_file>` 안내를 한 덩어리 끼워 넣는데, 수집기가 덩어리를 이어 붙인
> 뒤 첫 글자가 `<` 인지 봤다. 그래서 그 질문이, 나아가 그 대화가 사라졌다. 9/11 오전
> 이 저장소의 대화 3개 중 1개가 그렇게 빠져 있었다.

**세션 요약 — 무엇으로 정했나 (9/11 정정)**

| 언제 만들까 | 판단 |
|---|---|
| 전송할 때마다 | ✗ 10분마다 세션 수만큼 LLM 을 부른다 |

**아직 요약이 없는 대화만** 집으므로 "전송할 때마다 다시 부르는" 문제가 없다 — 위 첫 줄에서

**TODO·저장 이벤트 확인** — ✅ **9/11 확인.** 임시 저장소를 만들어 `// TODO:`·`// FIXME:` 를
