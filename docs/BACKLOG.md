### 초안을 에이전트가 통으로 요약하게 (F-1)

**지금은 LLM 이 초안을 쓰지 않는다.** 이게 피드백의 핵심이다.

- `DraftGenerator` 는 그날의 activity·session 행을 모아 `DraftTemplate.render()` 에 넘긴다. 이건 **LLM 호출이 없는 순수 문자열 템플릿**이다 (`DraftTemplate` 는 "순수 함수라 DB 없이 단위 테스트할 수 있다"고 주석에 적혀 있다).
- LLM 은 그 앞 단계에서 커밋을 **한 건씩** `summary` 한 줄로 요약할 뿐이다 (요약 파이프라인 2-7). 초안은 그 한 줄들의 나열이다.

피드백이 요구하는 건 반대다. **그날 로그 전체를 한 번에 읽고** 사람이 쓰듯 묶어 내는 것.
커밋별 한 줄을 이어 붙인 목록은 "묶어서 요약"이 아니다.

바뀌어야 하는 것:

| 영역 | 내용 |
|---|---|
| PRD | F3 의 "출력 템플릿 (Markdown, **고정**)"을 폐기하거나, 프롬프트의 출력 형식 가이드로 격하한다 |
| 생성 | `DraftGenerator` 가 `LlmProvider` 를 부른다. 입력은 그날의 커밋 메시지·PR·VS 세션·TODO·계획 메모 전부 |
| 컨텍스트 | 활동이 많은 날은 전부 못 넣는다. 커밋별 요약으로 1차 압축 → 하루치를 묶는 **2단 구조**가 현실적이다. 커밋 단위 요약은 그 압축 용도로 남긴다 |
| 비용 | 재생성이 지금은 공짜(문자열 조립)지만, 바뀌면 매번 LLM 호출이다. 재생성 버튼 연타에 대한 판단이 필요하다 |

담당자 2 (F3a). **PRD F3 를 먼저 고쳐야 한다** — 계약 변경은 문서 먼저.

### 코드 변경 이력을 실제로 보여주기 — 소스트리처럼 (F-2)

초안 편집 화면 오른쪽 근거 패널은 지금 활동의 **제목·요약·`+N −M` 숫자만** 보여준다.
변경된 파일 목록도, diff 본문도 없다.

DB 는 자리만 있고 비어 있다. 확인한 결과다.

- `activities.raw_diff` — 컬럼은 V1 부터 있는데 **수집기가 채우지 않는다.** 프론트에서 읽는 곳도 없다
- `GET /activities/{id}` 의 `ActivityDetailResponse` 에 `rawDiff` 필드가 **이미 선언돼 있다.** 값이 항상 null 일 뿐이다
- 반대로 VS 세션은 `uncommitted_files[].diff` 에 **실제 diff 가 들어온다** — 미커밋 작업 쪽은 재료가 이미 있다

할 일:

1. **수집** (담당자 2) — GitHub 커밋 상세(`/repos/{o}/{r}/commits/{sha}`)의 `files[]` 를 저장하거나, 열람 시점에 GitHub 에서 가져온다. 통째로 저장하면 DB 가 빠르게 커진다. **파일 목록·통계는 저장하고 diff 본문은 온디맨드**가 무난하다
2. **화면** (담당자 1) — 근거 패널을 파일 트리 + diff 뷰어로 확장한다. 소스트리 느낌이면 좌: 커밋 목록 / 우: 변경 파일 / 하: diff 의 3단이다. **디자인 브리프 3.3 에 없는 화면이라 브리프부터 고쳐야 한다**
3. F-1 과 붙어 있다 — 에이전트가 diff 를 읽으면 "무엇을 왜 고쳤는지"가 나온다. 커밋 메시지만으로는 안 나온다

**둘 중 큰 쪽은 수집이다.** 화면은 diff 만 오면 라이브러리로 붙는다.

### 회원 발급은 관리자가 이메일 요청을 받아 아이디를 준다 (F-4 · F-5)

§2 의 회원 체계 도입은 이미 결정돼 있었고, 어제 피드백으로 **가입 방식이 정해졌다.**

- 공개 셀프 가입 폼이 아니다. **이메일로 요청 → 관리자가 계정을 발급 → 본인이 받아 로그인**하는 초대형이다
- 그래서 가입 승인 대기나 이메일 인증 발송이 필요 없다. §2 에 적어 둔 "회원가입 폼"은 **관리자용 계정 발급 화면 + 최초 로그인 시 비밀번호 변경**으로 바뀐다. 구현이 오히려 줄어든다
- 대신 **관리자 역할이 새로 필요하다.** 지금 `users` 에 role 컬럼이 없다 (V1 확인). §2 의 V4 마이그레이션에 `role` 을 같이 넣는다
- F-4("관리자는 모든 기여자가 다 보여야")는 회원만 보이는 지금 구조로는 안 된다 — §3-4 와 같은 뿌리다. 관리자가 미가입 기여자(`external_login`)를 보고 **그 자리에서 계정을 발급해 연결**하는 흐름이 자연스럽다

"클로드한테 물어볼까" 하신 부분 — 발급 흐름의 선택지는 셋이다.

| 방식 | 내용 | 비용 |
|---|---|---|
| **A. 관리자 수동 발급** | 관리자가 이름·이메일·부서를 넣어 계정 생성, 초기 비밀번호를 직접 전달 | 가장 싸다. 메일 발송 인프라가 필요 없다 |
| B. 초대 링크 | 관리자가 이메일을 넣으면 1회용 링크 발급, 본인이 열어 비밀번호 설정 | 메일 발송 또는 링크 수동 전달 |
| C. 셀프 가입 + 승인 | 누구나 신청하고 관리자가 승인 | 피드백 취지와 다르다 |

**A 를 권한다.** 인원이 팀 규모이고 메일 발송 인프라가 없다. B 는 링크를 수동 전달하면 A 와 비용이 같아지므로 나중에 얹을 수 있다. 결정은 §5 로 올린다.

### VS 연동을 설치해서 테스트할 수 있게 (F-6)

계획의 1-12 와 같은 항목이지만, 피드백이 요구하는 건 패키징이 아니라 **남이 설치해서 쓸 수 있는 상태**다.

지금 확장은 `vscode` 모듈을 흉내 낸 하네스로만 검증했고 **실제 VS Code 에 설치한 적이 없다.** 남은 것:

- `vsce package` → `.vsix`
- 설치 후 첫 실행 경로: 서버 주소·API Key 입력 → 저장 → `지금 전송` → 대시보드에 뜨는지
- **API Key 를 받으려면 웹에 로그인이 돼 있어야 한다.** 즉 F-5 의 회원 발급이 없으면 GitHub 계정을 가진 사람만 테스트할 수 있다. 사용자 테스트 대상이 좁아진다
- 3일차 안에 이게 안 되면 "사용자 테스트"라는 요구 자체가 성립하지 않는다. **1-12 의 우선순위를 올린다**

"별로임" 한 줄이라 **무엇이 별로인지가 없다.** 추측으로 고치면 두 번 일한다.

지금 상태: 디자인 브리프대로 shadcn/ui + Tailwind 로 구현했다. 그런데 브리프 자체가 얇다 —

갈래를 좁히기 위한 질문:

- **시각**(색·여백·타이포·컴포넌트 만듦새)인가
- **정보 구조**(무엇이 어디에 있는지)인가 — F-2 의 diff 뷰가 들어가면 초안 편집 화면은 어차피 다시 짜야 한다

**요청**: 어느 화면의 무엇이 걸리는지 **한 화면만** 짚어 주시면 그걸 기준으로 나머지를 맞춘다.

## 2. 기획 변경 — 자체 회원 체계

### 배경

3일차 논의에서 나온 요구사항 셋 중 두 개가 **현재 인증 구조로는 만족되지 않는다.**

1. 등록한 리포의 **기여자 정보가 모두** 떠야 한다
2. 조회는 팀 전체 공개, **등록·전송은 본인 것만**
3. 한 기기에서 **여러 사람이 로그인·로그아웃** 할 수 있어야 한다

### 지금 구조와 그 한계

`users` 행을 만드는 유일한 경로가 GitHub OAuth 콜백이다. 즉 **GitHub 로그인이 곧 회원가입**이다.

```
users (github_id UNIQUE, login UNIQUE, name, avatar_url, github_token_enc)
  ↑ 이메일도 비밀번호도 부서 정보도 없다
```

로그인하지 않은 사람은 시스템에 존재하지 않으므로, 아래가 **구조적으로 불가능**하다.
실제 DB 확인 결과다.

```
UngsikJo (미가입) | 커밋 26 | VS 세션 0 | 초안 0
```

- `api_keys.user_id` NOT NULL → 회원이 아니면 API Key 를 못 받고, VS Code 확장을 연동할 수 없다
- `vscode_sessions.user_id` NOT NULL → 세션 자체가 존재할 수 없다
- `drafts.user_id` NOT NULL → 초안 생성 대상이 아니다

GitHub 커밋만 `external_login` 으로 남는다. **그 사람의 VS 작업과 업무 일지는 아예 없다.**

### 결정

**자체 회원가입을 도입한다.** 이유는 둘이다.

1. **팀원 목록을 미리 관리한다** — 관리자가 회원을 등록해 두고, 각자 자기 계정에 GitHub·VS Code 를 연결한다. 지금은 본인이 GitHub 로그인을 하기 전까지 시스템에 아무 자리도 없다.
2. **사내 정보를 받는다** — 이름·이메일·부서 같은 값은 GitHub 프로필에 없다.

즉 회원이 먼저 있고, **GitHub 과 VS Code 는 그 회원에 붙는 연동 수단**이 된다. 지금은 GitHub 이 곧 정체성이라 순서가 반대다.

### 바뀌어야 하는 것

| 영역 | 내용 |
|---|---|
| 스키마 | `users` 에 email · password_hash · 부서 등 추가, `github_id`/`login` 을 NULL 허용으로. **V4 마이그레이션** |
| 인증 | 자체 로그인으로 JWT 발급. GitHub OAuth 콜백의 의미가 "로그인" → **"내 계정에 GitHub 연동"** 으로 바뀐다 |
| 화면 | 회원가입 · 로그인 폼 · 연동 관리 화면 신규. 디자인 브리프 3.1 은 "GitHub로 로그인" 버튼 **하나**뿐이라 재설계가 필요하다 |
| 문서 | PRD §5 F5(인증), §6 데이터 모델, §12 확정된 가정을 다시 쓴다 |
| 코드 | 담당자 2 의 `auth/` 전반, 담당자 1 의 `LoginPage`·`AuthDonePage`·`RequireAuth` |

### 비용과 판단

**1~2일 규모다.** 3일차 하루에 착수하면 지금 동작하는 인증까지 흔들린다.
그래서 **이번 프로젝트 범위 밖으로 두고, 다음 작업으로 넘긴다.**

착수할 때 순서 제안:

1. PRD §5 F5 · §6 · §12 를 먼저 고친다 (계약 변경은 문서 먼저 — 프로젝트 규칙)
2. 디자인 브리프에 회원가입 · 로그인 · 연동 관리 화면을 추가하고 Figma 로 확정
3. V4 마이그레이션 → 자체 인증 → GitHub 연동 전환 → 화면
4. 기존 GitHub 전용 계정의 이관 경로를 정한다 (기존 `users` 행에 이메일을 나중에 채우는 방식 등)

## 3. 9/9 에 발견한 문제

### 3-1. 리포 삭제에 소유자 검사가 없다 🔴 (담당자 2)

```java
// RepoService.delete — 소유자 확인이 없다
public void delete(Long repoId) {
    Repo repo = repoRepository.findById(repoId).orElseThrow(...);
    repoRepository.delete(repo);
}
```

**팀원 누구나 남이 등록한 리포를 지울 수 있다.** `activities.repo_id` 가 `ON DELETE CASCADE` 라
그 리포의 활동 기록이 통째로 사라진다. 화면의 휴지통 아이콘 한 번이면 된다.

요구사항 2("등록·전송은 본인 것만")에 직접 걸리고, 그 이전에 사고 위험이다.
`registered_by != principal.id()` 면 403 으로 막아야 한다.

**함께 정할 것**: 동기화(`POST /repos/{id}/sync`)도 소유자만 할지. 읽기성 갱신이라
팀 누구나 눌러도 무해할 수 있다.

### 3-2. `POST /drafts/{id}/notify` 가 확정 여부를 검사하지 않는다 🔴 (담당자 2)

```java
// DraftNotifyController — 초안 존재만 확인하고 바로 전송한다
Draft draft = draftRepository.findById(id).orElseThrow(...);
if (!notifyService.notifyDraftContent(draft)) { ... }
```

DRAFT 상태 초안으로 호출해도 전송 단계까지 간다 (지금은 webhook 미설정이라 503 이 날 뿐).

디자인 브리프 3.3 은 "Mattermost 전송은 **확정 후에만** 활성", PRD F3 도 확정본을 보내는 흐름이다.
화면은 버튼을 잠가 막지만, API 직접 호출이나 `/external/*` 연동에서는 미확정본이 나갈 수 있다.
**webhook URL 이 붙는 순간 실제로 발생 가능하다.**

`status != CONFIRMED` 면 `409 DRAFT_NOT_CONFIRMED` 로 막아야 한다.
담당자 1 의 목업은 이미 그 규칙으로 동작하므로, 서버만 맞추면 양쪽이 같아진다.

### 3-3. 로그아웃 UI 가 없다 🔴 (담당자 1)

`auth.clear()` 는 401 을 받았을 때만 호출된다. 화면에 로그아웃 수단이 없다.

- 토큰이 localStorage 에 12시간 남는다
- 다른 사람이 쓰려면 주소창에 `:8080/api/auth/github` 를 직접 쳐야 한다. 동작은 하지만 화면에서 할 방법이 없다
- **디자인 브리프 2. 의 상단 바가 "날짜 선택기 + 아바타" 뿐이라 기획 단계에서 빠졌다**

아바타 클릭 → 사용자 이름 + 로그아웃 드롭다운이면 충분하다. 브리프에 없는 요소지만
없으면 서비스가 성립하지 않는다. **반나절 안 걸린다.**

### 3-4. 미가입 기여자가 화면에 안 뜬다 🟡

`HomePage.tsx` 가 `a.user !== null` 로 거르고, 사용자 카드는 `/stats/daily` 의 `byUser` 를 따른다.
`byUser` 는 매핑된 사용자만 담으므로 UngsikJo 의 커밋 26건이 화면에서 사라진다.

담당자 2 가 `unmapped` 필드를 추가해 **총계 = byUser 합계 + unmapped** 가 성립하게 해 줬고,
담당자 1 은 그 값이 0 이 아닐 때 안내 문구 한 줄을 띄운다. **근본 해결은 §2 회원 체계다.**
