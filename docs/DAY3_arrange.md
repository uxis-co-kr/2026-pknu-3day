## 2. 계획대로 안 풀려서 고친 것

### ① 비밀번호 변경이 절대 통과되지 않았다 — 네 겹

"로그인할 때마다 경고문이 뜬다" 는 한 증상에 원인이 넷이었다. 순서대로:

1. **길이 불일치** (`d20234a`) — 화면은 "4자 이상", 서버는 8자. 그 사이 길이는 늘 400
2. **메서드 불일치** (`7ce04ee`) — 화면은 `POST /me/password`, 서버는 `PUT` 만. 버튼이 405 로 막혔고, 500 "서버 오류" 가 그걸 가리고 있었다 → 405 를 제대로 돌려주게 함
3. **관리자까지 강제** (`f044f0a`) — 사원번호는 공개 정보라 강제할 이유가 있지만 관리자 비밀번호는 아니다
4. **브라우저 표시를 믿음** (`0876599`) — `localStorage` 표시가 한 번 켜지면 풀 방법이 없었다. `GET /me` 가 `mustChangePassword` 를 돌려주고 화면은 그것만 따른다

> 담당자 1 이 같은 날 회의 결정으로 **"강제하지 않는다"** 로 바꿨다(`908839b`). 서버 값은 이제 설정 화면의 안내 조건으로만 쓴다. 병합 결과가 뜻이 맞는지 확인함.

### ② Mattermost Outgoing Webhook 이 막혔다 → 봇 계정으로 방향 전환

처음엔 Mattermost 가 우리를 부르는 Outgoing Webhook 으로 만들었다. 그런데 사용자 계정에 **통합 메뉴 자체가 없었고**, 있더라도 사내 IP 로 나가는 웹훅은 Mattermost 가 기본으로 막는다(시스템 콘솔 필요).

그래서 방향을 뒤집었다 — **우리가 일반 회원 계정으로 로그인해 채널을 읽는다.** 로그인 API 는 권한이 필요 없고 연결도 우리 쪽에서 연다. Outgoing Webhook 경로(`/chat/mattermost`)는 남겨 뒀다.

봇 계정이 사람 계정과 같을 수 있어서(시연은 `@ungsikjo` 로), "내 글" 이 아니라 **"봇이 쓴 답"만 무시**한다 — 답에 `props.worklog_bot` 표시를 붙인다 (`83596db`).

### ③ 관리자에서 내렸는데 아직도 관리자

JWT 에 `role` 을 적어 두고 그것으로 인가했다. 권한을 내린 뒤에도 옛 토큰은 만료(12시간)까지 관리자였다. 재현: 9998 을 관리자로 만들어 토큰 발급 → 내림 → 옛 토큰으로 `/admin/overview` 200. 고친 뒤 403. 요청마다 사용자를 읽는다 (PK 조회 1번).

### ④ 팀원 내역이 비어 있다 → 실은 500

`admin`, `9998` 은 GitHub 이 없어 `login` 이 null. 인원별 통계가 그걸로 정렬하다 NPE. 자체 로그인을 만든 뒤 생긴 회귀. `login` 이 없으면 사원번호·아이디를 대신 쓴다.

그리고 콘솔이 **사용자 화면(/people)을 그대로 빌려 쓰고** 있어서, 한 사람만 불러오는 그 화면 특성 때문에 드롭다운에 관리자 하나만 나왔다. 전원 집계 페이지를 따로 만들었다 (`896da7f`).

### ⑤ GitHub 연동이 `OAUTH_STATE_MISMATCH`

화면은 `192.168.1.218:5173`, 콜백은 OAuth App 에 등록된 `localhost:8080`. state 를 **쿠키**에 두니 다른 호스트에 심겨 콜백에 안 따라왔다(로그에 `expected=null`). "누구에게 붙일지" 를 담은 link 쿠키도 같이 사라져, 성공했더라도 새 계정이 생길 뻔했다.

→ **state 자체에 서명** (`OAuthStateCodec`): nonce · 만료 5분 · 붙일 사용자 id 를 HMAC 으로. 어느 호스트로 콜백이 와도 위조·만료만 막으면 된다. 검증: 사내 IP 로 시작한 state 로 `localhost:8080` 에 쿠키 없이 콜백 → 통과, 한 글자 바꾼 state → 400.

`GITHUB_REDIRECT_URI` 로 콜백 주소를 못 박을 수 있게 했다 — 다른 기기에서도 연동하려면 OAuth App 에 사내 IP 주소를 등록하고 여기에 적는다.

### ⑥ 사원번호 9999 로그인이 500

`9999` 가 이미 UngsikJo GitHub 계정에 이어져 있어서(`uq_users_employee`) 새 계정을 만들다 터졌다. **이미 이어진 계정이 있으면 로그인 수단만 붙인다.** 한 사람이 계정 둘을 가지면 활동이 갈린다.
