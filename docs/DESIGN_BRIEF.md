# 디자인 브리프 — WorkLog Drafter 대시보드

Claude Design 입력용. 이 문서에 없는 화면·요소는 만들지 않는다. 결과는 Figma로 내보내 팀 리뷰 후 확정한다.

---

## 1. 제품

**WorkLog Drafter**는 개발자의 하루 GitHub 활동(커밋·PR·머지)과 VS Code 안의 미커밋 작업을 자동으로 모아 **업무 일지 초안**을 만들어 주는 사내 웹 도구다. 개발자는 초안을 열어 고치고 확정하며, 확정본은 Mattermost로 보낼 수 있다.

**사용자**
- 개발자(1차): 매일 저녁 자기 초안을 받아 5분 안에 다듬고 확정한다.
- 팀 리드(2차): 오늘 팀원들이 무엇을 했는지 한 화면에서 훑는다.

**핵심 사용 흐름**
로그인 → 홈에서 오늘 활동 확인 → "초안 생성" → 초안 편집 → 확정 → (선택) Mattermost 전송

---

## 2. 스타일 제약

- 데스크톱 전용, **1440 × 900** 아트보드. 모바일 없음. 다크 모드 없음.
- 톤: 담백한 사내 관리자 대시보드. 화려한 일러스트·그라데이션 없이 정보 밀도와 가독성 우선.
- 구현은 **shadcn/ui + Tailwind**로 하므로 그 컴포넌트 어휘(Card, Table, Badge, Button, Tabs, Select, Textarea, Dialog, Sheet)로 표현 가능한 형태로 그린다.
- 공통 레이아웃: 좌측 고정 사이드바(로고 + 5개 메뉴: 홈 / 초안 / 리포 / 인원 / 설정) + 상단 바(날짜 선택기, 현재 사용자 아바타). 콘텐츠 영역 최대 폭 1200.
- 타이포: 시스템 산세리프(Pretendard 계열). 본문 14px, 표 13px.
- 색: 중립 그레이 베이스 + 포인트 1색(파랑). 상태 배지만 의미색 사용 — DRAFT 회색, CONFIRMED 초록, FAILED 빨강, 미커밋 경고 주황.
- 활동 타입 아이콘 3종: COMMIT(커밋 아이콘), PR_OPENED(PR 아이콘), PR_MERGED(머지 아이콘, 보라 계열).

## 3. 화면 목록 (6개)

### 3.1 로그인 `/login`
- 가운데 정렬 카드 하나. 제품명, 한 줄 설명("GitHub 활동으로 업무 일지 초안을 자동 생성합니다"), **"GitHub로 로그인"** 버튼(GitHub 아이콘 포함).
- 하단에 작은 회색 텍스트: "사내 전용 · 팀 리포지터리 읽기 권한이 필요합니다".

### 3.2 홈 — 일별 보드 `/` (가장 중요한 화면)
상단 바의 날짜 선택기가 이 화면을 지배한다. 기본값 오늘(2026-09-09), 좌우 화살표로 하루씩 이동.

**A. 요약 카드 4개 (가로 한 줄)**
| 카드 | 값 | 보조 텍스트 |
|---|---|---|
| 커밋 | 12 | 어제 대비 +3 |
| PR | 3 | 열림 3 · 머지 1 |
| 머지 | 1 | — |
| 미커밋 세션 | 2 | ⚠ 6시간 이상 1건 |

**B. 필터 바**: 리포 Select(전체 / withly/punchcheck / withly/salty-web), 사용자 Select(전체 / 배태일 / 김민수 / 이서연), 타입 토글(커밋·PR·머지·미커밋).

**C. 사용자별 활동 타임라인** — 사용자 카드가 세로로 쌓인다. 각 카드:
- 헤더: 아바타 + 이름 + 오늘 건수 요약("커밋 2 · PR 1 · 머지 1 · 미커밋 1") + 우측 버튼 **"초안 생성"** (이미 초안이 있으면 **"초안 열기"** + 상태 배지 DRAFT/CONFIRMED).
- 본문: 시간순 활동 행. 각 행 = 시각(10:12) · 타입 아이콘 · 리포 배지 · 제목 · LLM 요약 한 줄(회색, 말줄임) · 우측에 +120 −8 같은 변경량. 요약이 아직 없으면 "요약 생성 중…" 스켈레톤, 실패면 빨간 "요약 실패" 배지.
- 미커밋 세션 행은 배경을 연한 주황으로 구분: 브랜치명 `feature/attendance`, "미커밋 4파일 · 마지막 커밋 6시간 전", TODO 2건, 계획 메모 인용.

**예시 값 (이 값을 그대로 쓸 것)**
- 사용자: 배태일(taeil), 김민수(minsu-kim), 이서연(seoyeon-lee)
- 리포: withly/punchcheck, withly/salty-web
- 배태일의 오늘 활동:
  - 10:12 COMMIT `abc1234` withly/punchcheck "feat: 출석 API 추가" — 요약: "출석 체크 REST API를 추가하고 중복 출석을 막는 검증 로직을 넣었습니다." +120 −8
  - 11:40 COMMIT `d9e8f71` withly/punchcheck "fix: 출석 시각 타임존 오류" — 요약: "출석 시각이 UTC로 저장되던 문제를 KST 기준으로 수정했습니다." +14 −6
  - 14:05 PR_OPENED #12 withly/punchcheck "출석 API 및 타임존 수정"
  - 16:30 PR_MERGED #11 withly/salty-web "온보딩 화면 리팩토링"
  - 미커밋: `feature/attendance` · 4파일 · TODO "중복 출석 검증 테스트 추가" · 계획 메모 "오후에 출석 중복 검증 로직 마무리"

### 3.3 초안 편집 `/drafts/:id`
좌우 분할(약 60 : 40).

**좌측 — 에디터**
- 헤더: 제목 "2026-09-09 업무 일지 — 배태일", 상태 배지 DRAFT, 버전 "v1", "마지막 저장 18:02".
- Tabs: **편집** / **미리보기**. 편집은 Markdown Textarea(고정폭 아님, 일반 폰트), 미리보기는 렌더된 Markdown.
- 하단 버튼 줄: 좌측 **재생성**(아이콘 버튼, 보조), 우측 **저장**(보조) · **확정**(주요, 파랑) · **Mattermost 전송**(보조, 확정 후에만 활성).
- 확정 상태(CONFIRMED)일 때는 에디터가 읽기 전용이 되고 배지가 초록, "확정 2026-09-09 18:10" 표시. 이 상태의 변형도 아트보드 하나로 그린다.

**우측 — 근거 패널**
- 제목 "이 초안의 근거".
- 섹션 1 "GitHub 활동 (4)": 홈의 활동 행과 같은 형식, 더 촘촘하게.
- 섹션 2 "미커밋 세션 (1)": 브랜치·파일 수·TODO 목록.
- 각 행 클릭 시 에디터의 해당 줄로 이동한다는 암시(hover 하이라이트).

**에디터 예시 본문 (그대로 사용)**
```
# 2026-09-09 업무 일지 — 배태일

## 완료한 작업
- [withly/punchcheck] 출석 체크 REST API를 추가하고 중복 출석을 막는 검증 로직을 넣었습니다. (commit abc1234)
- [withly/punchcheck] 출석 시각이 UTC로 저장되던 문제를 KST 기준으로 수정했습니다. (commit d9e8f71)
- [withly/punchcheck] PR #12 오픈: 출석 API 및 타임존 수정
- [withly/salty-web] PR #11 머지: 온보딩 화면 리팩토링

## 진행 중 / 미커밋
- [withly/punchcheck] feature/attendance — 출석 검증 테스트 4개 파일 작성 중 (미커밋)

## 계획 / TODO
- 중복 출석 검증 테스트 추가
- 오후에 출석 중복 검증 로직 마무리

## 메모
(직접 작성)
```

### 3.4 리포 관리 `/repos`
- 상단: 입력창 "owner/repo" + **등록** 버튼. 오른쪽에 "GitHub에서 접근 가능한 리포만 등록됩니다" 안내.
- Table 컬럼: 리포 이름(링크) · 기본 브랜치 · 오늘 활동 수 · 마지막 동기화(상대 시각 "8분 전") · 동기화 상태 배지(정상 / 진행 중 / 실패) · 액션(**동기화** 아이콘 버튼, **삭제** 아이콘 버튼).
- 예시 행: withly/punchcheck · main · 9 · 8분 전 · 정상 / withly/salty-web · main · 3 · 12분 전 · 정상.
- 빈 상태(리포 0개) 변형도 하나: 일러스트 없이 텍스트 + 등록 유도.

### 3.5 인원별 이력 `/people`
- 상단: 사용자 Select + 기간 Tabs(이번 주 / 이번 달 / 직접 선택).
- 상단 요약 카드 3개: 커밋 합계 / PR 합계 / 머지 합계.
- 막대 그래프 1개: 일별 커밋 수(x축 날짜 7일, y축 건수). Recharts 기본 스타일 수준으로 단순하게.
- 아래 Table: 날짜 · 커밋 · PR · 머지 · 초안 상태(배지) · "초안 열기" 링크.
**예시 값 (배태일, 2026-09-03 ~ 09-09)** — 아트보드 7 은 합계·9/9 행에 팀 전체 수치를 썼는데, 선택된 사용자 본인 기준으로 바로잡는다.

| 날짜 | 커밋 | PR | 머지 | 초안 상태 |
|---|---|---|---|---|
| 2026-09-09 | 2 | 1 | 1 | DRAFT |
| 2026-09-08 | 2 | 1 | 0 | CONFIRMED |
| 2026-09-07 | 4 | 0 | 1 | CONFIRMED |
| 2026-09-06 | 7 | 1 | 0 | CONFIRMED |
| 2026-09-05 | 0 | 0 | 0 | — |
| 2026-09-04 | 3 | 1 | 0 | CONFIRMED |
| 2026-09-03 | 5 | 0 | 1 | CONFIRMED |

- 요약 카드: 커밋 합계 **23** / PR 합계 **4** / 머지 합계 **3** (위 표의 열 합계)
- 막대 그래프(일별 커밋): 5 / 3 / 0 / 7 / 4 / 2 / **2**
- 9/9 행을 펼치면 홈과 같은 배태일의 활동 4건 + 미커밋 세션 1건이 나온다

### 3.6 설정 `/settings`
세 섹션이 세로로 쌓인 카드.
1. **API Key** (VS Code 확장·외부 연동용): 발급된 키 목록 Table(라벨 · 생성일 · 마지막 사용 · 폐기 버튼) + **새 키 발급** 버튼. 발급 직후 키를 한 번만 보여 주는 Dialog(복사 버튼, "다시 볼 수 없습니다" 경고)도 아트보드로 그린다. 예시 라벨: "MacBook VS Code", "Mattermost 봇".
2. **Mattermost**: Webhook URL 입력, "미커밋 리마인드 받기" 스위치, **테스트 전송** 버튼.
3. **LLM 모델**: 라디오 2개 — `gemma4` (google/gemma-4-26b-a4b-qat, 기본) / `qwen3` (qwen3.8:27b). 각 항목 옆에 연결 상태 점(초록/회색). 커스텀 입력 없음.
